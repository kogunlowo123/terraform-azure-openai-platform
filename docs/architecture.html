Microsoft Azure Terraform Module AI / ML

terraform-azure-openai-platform

Executive Summary

Terraform module for deploying Azure OpenAI Service with multi-model deployments (GPT-4, GPT-3.5 Turbo, embeddings), private endpoint networking, content filtering policies, user-assigned managed identity with RBAC, and an optional Azure API Management (APIM) front-end for rate limiting, authentication, and usage analytics. Includes diagnostic settings for full request/response audit logging.

1. Client sends request to APIM gateway URL. 2. APIM applies rate limiting, authentication, and request transformation. 3. Traffic routes through private endpoint to OpenAI service. 4. Content filter evaluates request before model processing. 5. Model deployment generates response. 6. All requests logged to Log Analytics (Audit + RequestResponse + Trace).

Security Controls

Network Security

- Private endpoint (public access auto-disabled)
- Private DNS zone integration
- Network ACLs with default Deny
- IP and VNet rule allowlists

Identity & Access

- User-assigned managed identity
- RBAC-based access (no shared keys)
- APIM subscription key authentication
- SystemAssigned identity on APIM

Content Safety

- Content filter policies on deployments
- Request/response audit logging
- Trace-level diagnostics available

API Governance

- Rate limiting via APIM policies
- Usage analytics and reporting
- Request routing and transformation
- Subscription-required API access

Industry Adaptation

Enterprise AI

APIM front-end for multi-team usage metering, managed identity auth, private endpoint for data isolation

Healthcare

Content filtering for sensitive data, private endpoint only, full audit logging, no public network access

Customer Service

GPT-3.5 for high-volume chat, GPT-4 for complex queries, rate limiting per application, usage analytics

Development Platforms

Embeddings model for RAG, multiple model deployments, APIM for developer portal and API key management

Production Readiness Checklist

  • Private endpoint enabled (public access disabled)
  • Managed identity for RBAC access
  • Content filter policy applied to deployments
  • Diagnostic settings with Audit + RequestResponse logging
  • Network ACLs with default Deny
  • Configure APIM for rate limiting and auth
  • Set appropriate SKU capacity per model deployment
  • Monitor token usage and throttling metrics
  • Test failover with regional deployments
  • Review content filter sensitivity levels
